# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

«Енисей» — SaaS-платформа для клубов настольного тенниса. Один продукт, один язык: TypeScript под pnpm 10 + Turborepo, Postgres 18. Документация — в `docs/`, обзор и быстрый старт — в `README.md`.

До 01.09.2026 под этим же корнем жил внешний проект — компилятор памяти на Python (`scripts/`, `hooks/`, `daily/`, `knowledge/`, `AGENTS.md`, `pyproject.toml`). Он снят: долгую память ведёт claude-mem, хранящий базу вне репозитория, в `~/.claude-mem/`. Если в старом коммите или в чужой ссылке встретится `uv run python scripts/compile.py` — этого больше нет, искать в истории git.

## Команды

Продукт (pnpm 10 + turbo, из корня):

```bash
pnpm dev            # apps/api и apps/web в watch-режиме
pnpm typecheck      # по всем пакетам
pnpm test           # node --test
pnpm smoke          # 255 сценариев против поднятого API и живого Postgres
pnpm db:migrate     # prisma migrate dev
pnpm db:studio
pnpm db:create-admin -- --email a@club.ru --password "..." --name "Иванов Иван"
pnpm db:seed-demo   # занятия и турниры на ближайшие дни (отдельно от сида: даты протухают)
```

Модули, которые гоняются через `node --test`, **не могут иметь относительных
импортов**: node требует расширение `.ts`, а сборка (`tsconfig.build.json`,
`allowImportingTsExtensions: false`) его не принимает. Поэтому чистые модули
вроде `club/closures.ts` и `booking/availability.ts` самодостаточны, а всё
внешнее приходит в них аргументами.

Один тест — напрямую, минуя turbo:

```bash
cd apps/api && node --test --experimental-strip-types src/auth/tokens.test.ts
```

Проверка схемы БД на одноразовой базе:

```bash
pnpm --filter @yenisey/database verify
```

`verify` разворачивает схему с нуля и намеренно пишет некорректные данные, проверяя, что база физически не даёт смешать данные двух клубов. **Направлять только на пустую одноразовую базу.** После `pnpm smoke` остаются учётки `probe-*@example.com` — убираются через `pnpm db:clean-probes`.

## Архитектура продукта

`apps/api` — NestJS. Модули `auth`, `tenants`, `users`, `club`, `booking`, `prisma`, `config`. `apps/web` — Next.js (app router). `packages/database` — Prisma, единственный владелец схемы. `packages/types` — общие типы, собирается через `tsc -p tsconfig.build.json`.

Клиент Prisma генерируется в `packages/database/generated/` и **в git не попадает** — после свежего клона и после правки схемы нужен `pnpm db:generate`, иначе типы не сойдутся.

### Мультиарендность — главное ограничение

Изоляция клубов держится на составных ключах и проверяется на уровне БД, а не только в коде. Точка входа человека в схему — не `User`, а `TenantMembership` (см. ниже). Правила схемы, которые нельзя нарушать:

- **Деньги — целые числа в копейках.** Не рубли с дробной частью. Конвертация только на границе представления.
- **Цену услуги считает сервер, и только он.** Форма показывает то, что вернул `GET /api/booking/quote`. Второй расчёт на клиенте разойдётся с первым молча.
- **Аренда тарифицируется начатыми получасами**, минимум — час без робота и полчаса с роботом. Логика — `apps/api/src/booking/pricing.ts`, там же тесты на прайс «Енисея».
- **Удаления нет.** Клиент деактивируется через `deactivatedAt`/`anonymizedAt`; на внешних ключах `onDelete: Restrict`.
- **Часть ограничений живёт в raw SQL.** `packages/database/prisma/constraints.sql` — 32 CHECK, 2 частичных уникальных индекса и 3 EXCLUDE (пересечение броней, шаблона недели и расписания дня). Prisma такое не выражает, поэтому при изменении схемы этот файл правится руками отдельно от миграции.
- **Цены, шаг брони и часовой пояс — у зала (`Hall`), а не у клуба.** Залы одной организации бывают в разных регионах, и общий на клуб пояс сдвинул бы в одном из них границы операционного дня и порог «за час до начала», от которого считаются деньги. У клуба остаётся то, что составляет договор с клиентом: политика неявки и правила абонемента.
- **Город указывается и у клуба, и у зала**, из справочника `City`, а не строкой. Поиск на стартовой странице находит клуб, если совпал **город клуба ИЛИ город хотя бы одного его зала** — правило ломается тише всего, поэтому оно закрыто смоук-сценарием, а не только типами.
- **Своих клубов не больше трёх.** Предел выражен структурой `UserClub`: слот уникален в пределах человека и ограничен диапазоном 1..3, поэтому четвёртый клуб физически некуда положить. Проверка в сервисе от гонки не спасает.

Сценарии на изоляцию — `packages/database/prisma/tests/schema-tests.sql`.

### Единый аккаунт: человек входит в схему через `TenantMembership`

`User` — **глобальная учётная запись платформы**. Клубу не принадлежит, роли
не несёт, почта уникальна по всей платформе. Всё клубное висит на
`TenantMembership` — паре «человек + клуб», которая несёт роль и клубное
отключение. Именно она, а не `User`, — мишень составных внешних ключей:
цепочка «бронь → анкета → привязка → (человек, клуб)» стала на звено длиннее,
но база по-прежнему не примет бронь со столом одного клуба и клиентом другого.

Что из этого следует при чтении кода:

- **Роли «вообще» нет.** `role` в профиле отсутствует; спрашивать роль без
  указания клуба бессмысленно. На сервере её даёт `ClubContextGuard`, на вебе —
  `roleInClub()` из `apps/web/src/lib/membership.ts`.
- **Клуб приходит участком адреса**, а не токеном: `/api/clubs/:slug/...`.
  Access-токен несёт только `sub`. Плата — запрос к базе на каждый клубный
  маршрут; выигрыш — снятая роль действует сразу, а не через 15 минут.
- **Порядок guard'ов в `auth.module.ts` единственно возможный**: токен →
  клубный контекст → роль. Перестановка даёт следующему guard'у пустоту.
- **Отключений два.** `User.deactivatedAt` — не пускает на платформу вовсе;
  `TenantMembership.deactivatedAt` — закрывает один клуб. Уволенный тренер
  «Енисея» продолжает играть в соседнем клубе.
- **Вступать в клуб, чтобы записаться, не нужно.** Человек без привязки
  проходит клубные маршруты как клиент, а `TenantMembership` заводится первым
  действием — см. `ensureClientMembership` в `booking.service.ts`. Проверять
  `joined`, а не только `role`, нужно везде, где сервис собирается писать.
- **Анкеты ролей ключуются парой** `(userId, tenantId)`, а не одним `userId`:
  один человек законно является клиентом в трёх клубах.

Миграция `20260902100000_platform_account` данные сохраняет и **сливает учётки
с одинаковой почтой**, оставляя самую свежую по `updatedAt`; все refresh-сессии
она гасит — формат токена изменился.

### Платформенный слой над клубами

Стартовая страница платформы клуба не имеет: на ней поиск по названию и
городу, а клуб открывается адресом `/clubs/:slug`. Отсюда несколько правил,
которые легко нарушить незаметно:

- **`TENANT_SLUG` больше не участвует в запросах.** Клуб приходит из адреса
  страницы: `clubApi(slug)` в `apps/web/src/lib/api.ts`, а страницы берут код
  хуком `useClubApi()`. Переменная окружения осталась запасным значением для
  разработки.
- **Открытый маршрут не значит анонимный.** `JwtAuthGuard` на `@Public()`
  всё равно разбирает предъявленный токен и просто не отказывает, когда его
  нет. Без этого открытый список мероприятий не мог бы ответить вошедшему на
  вопрос «а я записан?».
- **Обновление сессии — single-flight** (`refreshOnce` в `lib/api.ts`).
  Refresh-токен ротируется, а повторное предъявление отозванного сервер
  считает кражей и гасит ВСЕ сессии человека. Два параллельных обмена одной
  кукой (шапка и страница спрашивают профиль одновременно) выбрасывали из
  аккаунта во всех вкладках. Любой новый способ обновить сессию обязан идти
  через это же обещание.
- **Мероприятий два вида — занятия и турниры.** Различает их поле `kind` у
  `ClubEvent` и `BookingEntry`, и по нему же веб выбирает маршрут записи:
  `trainings/:id/booking` против `tournaments/:id/registration`. Сборка строки
  мероприятия — одна на всех, `apps/api/src/events/event-view.ts`: её зовут и
  открытый список клуба, и лента на стартовой странице, и разойтись им нельзя.
- **Занятие и турнир заводятся в расписании зала, а не формой.** Администратор
  выбирает кисть, тип, тренера и число мест и закрашивает время; при сохранении
  дня `resolveEvents` в `ScheduleCard.tsx` создаёт `TrainingSession` (одно на
  пару «тип + тренер», границы — по всем закрашенным окнам) и `Tournament`
  (один на тип и дату). В шаблоне недели ни того, ни другого быть не может: у
  них конкретная дата, а шаблон повторяется — там остаются только типы.
- **Лимит мест держит блокировка строки, а не констрейнт.** Проверка «занято
  меньше, чем мест» требует подсчёта строк в другой таблице, и двумя
  параллельными запросами обходится. `registerForTraining` берёт
  `SELECT ... FOR UPDATE` по сессии — рецепт записан в `constraints.sql`,
  раздел 4. У турнира лимита мест нет вовсе.
- **Состав записавшихся сокращает сервер.** `shortName` живёт в
  `packages/types`, потому что применяют его обе стороны; полные имена чужих
  людей в браузер не уходят.
- **Список записей живёт в одном месте.** `EntriesService` собирает и «Мои
  записи» по всем клубам, и блок «Мои мероприятия» на странице клуба. Отмена
  идёт клубным маршрутом: платформенный дубль разошёлся бы с ним в деньгах.
- **Аренда стола попадает в «мои», но не в публичные списки**: к чужой броне
  стола нельзя присоединиться.

### Окружение

`.env` — один на весь монорепозиторий, в корне, в git не попадает. Переменные валидируются при старте API в `apps/api/src/config/env.ts`, приложение падает сразу. Отдельно проверяется, что `JWT_ACCESS_SECRET` и `JWT_REFRESH_SECRET` различаются: при совпадении refresh-токен принимается как access и обходит короткий срок жизни.

Подробности первого запуска и известные ограничения каркаса — `docs/DEVELOPMENT.md`. Техзадание — `docs/TZ.md`.

## Особенности этой машины (Windows)

- **Claude Code CLI без git-bash не стартует** и сообщает наружу только `exit code 1`. Настоящая ошибка уходит в stderr дочернего процесса, поэтому всё, что запускает CLI программно, должно этот stderr перехватывать — иначе диагностировать нечего. Путь: `X:\Git\bin\bash.exe` (не `System32\bash.exe` — это launcher WSL, и он не подходит).
- **Консоль в cp1251.** `print` с `₽`, эмодзи или длинным тире падает с `UnicodeEncodeError`, а `logging` молча теряет строку — скрипт успевает сделать работу и потерять результат на выводе. В Python-скриптах проекта ставь `PYTHONIOENCODING=utf-8` или перенастраивай `sys.stdout` первой строкой, а всем `basicConfig` задавай `encoding="utf-8"`.
- **`core.autocrlf=true`.** Контрольные суммы вендоренных скиллов в `.claude/skills/` считаются по LF-байтам, поэтому в `.gitattributes` для них стоит `text eol=lf`. Без этого свежий чекаут даёт «stale snapshot» и скилл молча не грузится.
- **TLS нестабилен.** `git push` периодически падает с `schannel: failed to receive handshake` — повторить. Проверяй код возврата именно `git`: `git push | tail -3` всегда вернёт 0.
- Образы с Docker Hub не тянутся (TLS-таймаут), Postgres установлен нативно.
